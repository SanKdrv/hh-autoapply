# hh-autoapply

Автономная система для поиска вакансий на hh.ru, генерации персональных
сопроводительных писем, отправки откликов и чтения ответов — с уведомлениями
в Telegram и запуском по расписанию.

## Что внутри

| Шаг | Модуль | Что делает |
|---|---|---|
| Поиск | `sources.py` | RSS-выдача hh (работает из-за рубежа), карточка вакансии из JSON-LD |
| Фильтр | `filters.py` | Стоп-слова, требование девелоперской роли, профильный стек |
| Скоринг | `scoring.py` | Балл релевантности + определение стека вакансии |
| Правила | `pipeline.py` | Удалёнка → автоотклик; офис/гибрид → только вручную, и лишь при зарплате ≥ порога |
| Письма | `letters.py`, `ai.py` | Через LLM (ключ в `.env`) или шаблоном как фолбэк |
| Отклики | `apply_selenium.py` | Selenium, рейт-лимиты, стоп на капче, защита от повторных откликов |
| Ответы | `inbox.py` | Чтение откликов из JSON страницы и чатов `chatik.hh.ru` |
| Аналитика | `analytics.py` | Сводка по воронкам: где больше ответов и приглашений |
| Логи | `notify.py` | Telegram-бот: сводки, новые ответы, ошибки |
| Расписание | `scripts/` | launchd (macOS) или cron |

## Честно о принципах работы

- **Отклик через официальный API hh невозможен**: из публичного OpenAPI убран
  метод отклика соискателя (`POST /negotiations` теперь = приглашение от
  работодателя). Поэтому отправка — через браузер, вход в аккаунт.
- **Автоотклик нарушает правила площадки.** Поэтому по умолчанию: 40/день,
  10 за цикл, паузы 90–300 с, длинный кулдаун каждые 8 откликов, остановка
  при капче. Не поднимай лимиты бездумно.
- **Selenium работает в отдельном профиле браузера** (`data/browser-profile`).
  Один раз нужно залогиниться в нём (`main.py login`) — дальше система работает
  автономно, и основной браузер можно не закрывать. Если хочется переиспользовать
  уже существующую сессию, поставь `browser.use_system_profile: true`, но тогда
  браузер придётся полностью закрывать перед каждым запуском.

## Установка

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env    # и заполни ключи
```

### `.env`

```dotenv
DEEPSEEK_API_KEY=sk-...            # ключ с platform.deepseek.com
LLM_BASE_URL=https://api.deepseek.com/v1
LLM_MODEL=deepseek-chat

TELEGRAM_BOT_TOKEN=123456:ABC...   # токен от @BotFather
TELEGRAM_CHAT_ID=123456789         # узнать у @userinfobot
```

Подходит любой OpenAI-совместимый провайдер — достаточно поменять `LLM_BASE_URL`
и `LLM_MODEL`. Если ключа нет, письма генерируются шаблоном, а промпты
складываются в `out/prompts/`.

## Команды

```bash
.venv/bin/python main.py run            # полный цикл (это вызывает планировщик)
.venv/bin/python main.py search         # только поиск и фильтрация
.venv/bin/python main.py letters --ai   # письма через LLM
.venv/bin/python main.py report         # HTML-очередь в out/queue.html
.venv/bin/python main.py login          # один раз: войти в аккаунт hh
.venv/bin/python main.py apply --once   # один пробный отклик
.venv/bin/python main.py inbox          # прочитать ответы работодателей
.venv/bin/python main.py bot            # Telegram-бот с управлением
.venv/bin/python main.py funnels --send # сводка по воронкам + отправить в Telegram
.venv/bin/python main.py drafts         # черновики ответов работодателю
.venv/bin/python main.py digest         # анализ логов, аномалии в Telegram
.venv/bin/python main.py notify-test    # проверить связь с Telegram
.venv/bin/python main.py stats          # статистика по базе
.venv/bin/python main.py calibrate      # снять разметку формы отклика
```

## Расписание

### launchd (macOS, рекомендуется)

```bash
./scripts/install_launchd.sh        # цикл: 10:00, 14:00, 18:00
./scripts/install_bot_launchd.sh    # Telegram-бот (постоянно)
./scripts/install_digest_launchd.sh # анализ логов ежедневно в 21:00
./scripts/uninstall_launchd.sh
```

Логи: `logs/agent.out.log`, `logs/agent.err.log`.

### cron

```cron
0 */4 * * * /Users/aleks/Documents/Default\ Project/hh-autoapply/scripts/cron_entry.sh
```

Важно: планировщик не сможет работать, пока открыт Edge (профиль занят).
Если автоотклик не критичен в конкретном запуске — используй `run --no-apply`.

## Telegram-бот с управлением

```bash
.venv/bin/python main.py bot          # запустить бота
./scripts/install_bot_launchd.sh      # держать бота постоянно запущенным
```

| Команда | Действие |
|---|---|
| `/status` | состояние: пауза, отправлено сегодня, очередь, новые ответы |
| `/funnels` | сводка по воронкам |
| `/queue [N]` | топ вакансий из очереди |
| `/keywords` | вакансии с кодовым словом |
| `/runs` | последние запуски |
| `/run [N]` | полный цикл (поиск → письма → отклики → ответы) |
| `/apply [N]` | только отправка откликов |
| `/letters` | перегенерировать письма |
| `/pause`, `/resume` | приостановить/возобновить отправку |
| `/help` | справка |

Бот слушает только `TELEGRAM_CHAT_ID` из `.env` и игнорирует посторонние чаты.
Долгие задачи уходят в фон, чтобы бот продолжал отвечать.

## Кодовые слова в сопроводительном

Часть вакансий требует указать в письме кодовое слово («укажите слово "ёжик"»,
«начните письмо со слова Привет», «кодовое слово: БАРСИК»). Такие требования
распознаются автоматически (`keywords.py`), слово ставится **первым** в письме,
в промпт LLM добавляется явное требование, а в очереди появляется бейдж 🔑 и
команда `/keywords` в боте. Без этого письмо часто отсеивается автоматикой.

## Хостинг 24/7

Честно: бесплатный хостинг для этой задачи подходит плохо.

- **GitHub Actions / Render / Fly.io** — датацентровые IP. hh отдаёт с них
  капчи и ограничения (мы уже видели `403` на API из-за геоблока), у бесплатных
  тарифов нет постоянного диска и состояния.
- **Oracle Cloud Free Tier** — реальная бессрочно-бесплатная VM, но IP тоже
  датацентровый: поиск и письма поедут, а автоотклик будет упираться в капчу.
- **Рабочий вариант** — домашняя машина (планировщик launchd), Raspberry Pi
  или домашний сервер: домашний IP, живая сессия, никаких капч.

Для серверного запуска есть `Dockerfile` (Chromium + headless):

```bash
docker build -t hh-autoapply .
docker run --rm -it --env-file .env -v "$PWD/data:/app/data" hh-autoapply login
docker run -d --name hh --env-file .env \
  -v "$PWD/data:/app/data" -v "$PWD/letters:/app/letters" -v "$PWD/out:/app/out" \
  hh-autoapply
```

## Диалог с работодателем

Система **не отвечает сама** — она готовит черновик и присылает его в Telegram
с кнопками:

**✅ Отправить** · **🔄 Переписать** · **✖️ Пропустить**

По нажатию «Отправить» бот вписывает текст в чат hh и отправляет.

Политика ответов (настраивается в `config.json` → `dialog`):

| Тема | Поведение |
|---|---|
| Зарплата | модель считает вилку сама от опыта и сложности вакансии, но не выше вилки вакансии более чем на `max_uplift` (25%) и не ниже `floor_net` |
| Тестовое задание | соглашается, срок называет трезво (2–3 дня / до недели), просит критерии |
| Собеседование | не назначает время — передаёт инициативу кандидату |
| Новые технологии | «готов освоить», без обещания имеющегося опыта |
| Нестандартный сценарий | пишет `ESCALATE` → уведомление в Telegram, ответ не отправляется |

Что считается нестандартным и уходит человеку: анкеты на сторонних платформах,
запросы паспортных данных, условия оффера, конкретные даты и переезд, всё, где
нужно личное решение.

Отказы работодателей система не комментирует.

## Ежедневный анализ логов

Каждый вечер агент собирает хвосты логов и сводку базы, отправляет их модели и
присылает в Telegram только **аномалии**: ошибки, повторы, регрессии, зависшие
циклы, расхождения в цифрах. Если всё в порядке — в Telegram не приходит ничего
(либо `OK`, если включить `diagnostics.send_ok`).

Проверка вручную:

```bash
.venv/bin/python main.py digest
```

Перед отправкой из логов вырезаются токены и ключи.

## Защита от повторных откликов

- Статус вакансии (`applied` / `already`) хранится в SQLite и проверяется перед
  каждым откликом — повторно на ту же вакансию система не откликнется.
- После каждого запуска система **сверяется с реальным списком откликов hh**
  (`/applicant/negotiations`) и приводит статусы в соответствие с ним. Это
  источник истины: даже если подтверждение на странице не сработало, статус
  будет исправлен.
- Как только по вакансии приходит входящее сообщение, она автоматически
  считается откликнутой.
- Отклики, отправленные вручную и не попавшие в наш поиск, тоже подхватываются
  в аналитику (воронка «Вне поиска»).

## Аналитика по воронкам

`main.py funnels` строит таблицу: сколько откликов ушло по каждой воронке
(Go, Python, PHP / WordPress, Go + Python), сколько пришло ответов, сколько
приглашений и отказов. Приглашения и отказы определяются по тексту сообщений
(«приглашаем», «собеседование» / «к сожалению», «выбрали другого»).

Та же сводка автоматически уходит в Telegram в конце каждого цикла.

## Настройка

`config.json`:

- `searches[]` — поисковые профили. `area`: `113` — вся Россия, `2` — Санкт-Петербург;
  `schedule: remote` — только удалёнка.
- `filters.exclude_title` / `require_title_any` — стоп-слова и обязательные слова в заголовке.
- `salary.relocate_min` — минимальная зарплата, при которой офисную вакансию
  вообще оставляем в очереди (ниже — отсекаем).
- `scoring.*` — веса ключевых слов.
- `rate_limits` — дневной лимит, паузы, рабочие часы.
- `schedule` — интервал планировщика и лимит откликов за цикл.
- `notify.telegram` — уведомления (ключи читаются из `.env`).

`profile.json` — ваш профиль для писем: достижения по стекам, контакты,
образование. Тексты попадают в письма как есть (в режиме шаблона).

## Если hh поменяет вёрстку

`main.py calibrate` откроет первую вакансию из очереди, снимет все `data-qa` в
`out/debug/calibrate_dom.txt` и сделает скриншот. По ним правятся списки
селекторов в `apply_selenium.py`. Для чтения переписки дамп страницы сохраняется
в `out/debug/inbox_dump.html`, если распознать её не удалось.

## Настройка профиля

Личный профиль кандидата (ФИО, контакты, достижения) в репозиторий не входит:
он лежит только локально в `profile.json` и добавлен в `.gitignore`. Для запуска
скопируй пример и заполни под себя:

```bash
cp profile.example.json profile.json
```

Ключи (LLM, Telegram) — в `.env`, см. `.env.example`.

## Важно: правила бирж

Проект автоматизирует действия на hh.ru, Хабр Карьере и SuperJob. Автоматические
отклики могут нарушать пользовательское соглашение этих площадок: используйте
на свой страх и риск, с разумными лимитами и паузами. Автор не несёт
ответственности за блокировку аккаунта или иные последствия применения.
